#### 2.24.1.1 基本原则

1. 适用于 `Development/Subsystems/` 下的子系统文档。
2. 本文档是子系统文档的通则, 具体子系统另有要求的, 覆盖或延伸本文档。
3. 程序文档采取白名单原则，只允许包含本文档显式要求的内容，不得自行拓展。
4. 程序文档只记录当前既定事实，不记录未实现内容、旧实现、版本迭代和构想；实现思路也不记录，除非在专属板块内。
5. 语言简练但内容须齐全。字数统一按“正文汉字数 + 英文单词数”计：去掉 Markdown 标记、空白、代码标识、标点、数字和专有名称；专有名称包括文件、类型、方法、字段、事件、子系统名。名称不计入字数。
6. 文档之间的字数比较（含“字数最多”）一律使用第 5 条口径，且不含标题与结构名。

#### 2.24.1.2 文档结构

严格按此结构：

- 子系统功能（负责什么，不负责什么，≤30字）
- 依赖的子系统及具体依赖业务（每个条目≤30字；只列项目内 `Basic2DPlatformer.*`，Unity 包不列）
- API（仅列其他程序集可依赖的入口；仅为 UnityEvent 暴露的 public 不列）
  - 字段（每个条目≤20字）
  - 事件（每个条目≤20字）
  - 公共方法（每个条目≤20字）
  - 空板块保留标题并写“暂无”
- 注意事项
  - 总则（如生命周期 / 每个条目≤30字）
  - 每个相关子系统单开一个板块（其下每个条目≤30字；只为有实际约束的依赖开板块）
- 内容
  - 根据文件夹结构梳理完整层级结构
  - 列出重要文件（若必要，≤15字定性）
  - `*.meta` 不列
- 实现思路（仅在跨文件协作或状态机 / 生命周期不直观时写）
  - 代码架构（≤30字）
  - 使用的范式
  - 内部方法 / 字段 / 事件等（仅罗列必要项和≤15字定性）
