# 代码注释规范

> 本工程代码注释的**唯一**标准。
> 依据:Microsoft C# 约定与 .NET、Google C# 风格的通行做法,并结合本工程的团队与文档现状。

## 0. 一句话

注释只解释 **为什么 / 契约 / 不变量 / 边界 / 副作用**;能靠命名表达的,不写注释。

## 1. 原则

1. **代码自解释优先**:好的命名 > 注释。
2. 注释解释 **why / 契约**,不复述 **what**。
3. **同步更新**:改动代码时必须同步更新注释;**过期的注释视为缺陷**。
4. **设计动机 / 架构 / 拓展点放 `Docs/`**(见 [ARCHITECTURE.md](ARCHITECTURE.md)、[EXTENDING.md](EXTENDING.md));注释不重复文档。
5. 注释是给**维护者**的:只写"看代码看不出来"的信息。

## 2. 语言

- **中文单一语言**。不写英文镜像,不写中英对照。
- 术语、类型名、API 名、关键字**保留英文原样**(如 `Rigidbody2D`、`FixedUpdate`)。

## 3. 哪些要写、哪些不写

| 对象 | 是否注释 |
| --- | --- |
| 类型(类 / 接口 / 结构 / 枚举) | **要** |
| public / internal / protected 方法 | **要** |
| public / internal / protected 属性、事件 | **要** |
| 接口成员 | **要** |
| 枚举成员 | 仅**非显然**者 |
| private 成员 | **不写**(靠命名) |
| 字段 | 仅**易混淆**时 |
| 序列化字段 | **不写注释,改用 `[Tooltip("...")]`** |
| 方法内联 | 仅当"为什么"非显然 |

## 4. 类注释模板

形如 XML `<summary>`(便于 IDE 悬浮),但**内容精简**:

- 第 1 行:**职责**,关键词或短句。
- 第 2 行:**归属 Subsystem**。
- 可选第 3 行:**不负责** —— 仅当边界容易混淆时(其余边界归 `Docs/`)。
- 确需描述实现时,**不超过 20 字**。
- **不写** `Where it lives` / `Lifetime` / `Paradigms` / `Data overview` 等固定清单。

```csharp
/// <summary>
/// 管理音频请求、池与并发上限.
/// 归属: Core (Audio).
/// </summary>
public class AudioManager : MonoBehaviour
```

## 5. 成员注释

- 单行说明**契约 / 副作用 / 边界**(返回值、异常、前置条件、可见后果)。
- **不要复述名字或代码**:`SetSpeed` 不要注释成"设置速度"。
- 没有额外约定时**不写**。
- 形式:单行 XML `<summary>`。

```csharp
/// <summary>首次播放会创建池, 之后复用.</summary>
public ISoundHandle Play(AudioId id, float volume)
```

## 6. 字段

- 默认不写;仅当含义无法从名字看出(单位、取值范围、业务含义)时写**一行**。
- **序列化字段一律用 `[Tooltip]`**,不写注释。

## 7. 内联注释

- 仅当"为什么这样做"不显然时写,**1–2 行**。
- 不写"做了什么"(代码已经显示)。

## 8. 反模式(禁止)

- 复述代码或方法名。
- 中英双语镜像 / 逐句对照。
- 注释掉的代码(交给版本控制)。
- 变更日志式注释(交给 commit / CHANGELOG)。
- 设计长文(移到 `Docs/`)。
- 过期注释。

## 9. 与文档的边界

- `Docs/` = 设计动机、架构、拓展点、长契约。
- 注释 = 代码本地信息。
- 两者**不重复**;确需长解释时,注释写一句并链接文档。

## 10. TODO / FIXME / HACK

- `TODO: <待办> —— <未做原因>`
- `FIXME: <已知缺陷> —— <原因>`
- `HACK: <临时手段> —— <原因>`
- **每条必须含原因**;格式可用正则校验。

## 11. region

- **不写自定义 `#region`**(如 `#region APIs`)。
- 仅使用条件编译分区(`#if UNITY_EDITOR` 等)。

## 12. 文件头

- **不写**常规文件头(类型名即文件说明)。
- **生成 / partial 文件**在顶部注明 `// 生成物, 勿手改.`。

## 13. 标点与用词

- 中文标点;**短句**;**句末不加句号**。
- 术语 / API 名原样英文。
- 不写无信息量的空话(如"这是一个类")。

## 14. 示例

```csharp
// 好: 解释 why / 契约
/// <summary>
/// 冷却严格按未缩放时间推进, 因此暂停期间仍会走完.
/// 归属: Core (Audio).
/// </summary>
public class AudioEmitter : MonoBehaviour

// 坏: 复述名字, 无信息
/// <summary>
/// AudioEmitter 类.
/// 用于发射音频.
/// </summary>
```

```csharp
// 好: 非显然的 why
// 复用 emitter 前必须先终结上一次播放, 否则池的租约不会回滚.

// 坏: 复述代码
// 把 velocity 设为 0.
body.velocity = Vector2.zero;
```

## 15. 强制与校验

- 本规范为**纯约定**:当前不引入 `.editorconfig` 规则或分析器(成员码风尚未统一)。
- 后续可选:模板自带**编辑器校验器**,检查公开成员是否带注释,并支持忽略标记。

## 16. 旧注释清理判定(供后续任务)

- **需重写**:中英双语镜像、超长类模板(`Where/Lifetime/Paradigms/Data` 清单)、private 成员注释、私有字段注释、复述式单行、注释掉的代码。
- **合规形态**:类型 = 一行职责 + 归属(+ 可选不负责);公开合约成员 = 一行契约;必要时内联 why;序列化字段用 `[Tooltip]`。
- **目标**:全库注释占比显著下降(重构前最高约 87%)。
